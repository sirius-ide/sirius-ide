Sirius is the default participant in the editor's chat view, so there is nothing to invoke:
open the chat (<kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>I</kbd>), type into *Describe what to
build*, press Enter. The mode picker in the input offers **Agent**, **Ask** and **Edit**;
Agent is where it starts.

## What happens to a message

Every message runs the same loop against the model you picked (or the chat view's own
choice):

1. Sirius sends the model its system prompt, your [project rules](/docs/rules-and-context/),
   the file you have open with the selection or the lines around the cursor, the earlier
   turns of the conversation, and what you attached: the text of attached files and
   selections (up to 100 KB each, and about half the model's context window in all; what
   does not fit, and binary files, go by path), and attached or pasted images for a
   [model that can see](/docs/image-input/). Instruction files the editor attaches —
   `AGENTS.md`, `CLAUDE.md` (including your personal `~/.claude/CLAUDE.md`, under the
   editor's `chat.useClaudeMdFile` setting), `*.instructions.md` — join the instructions
   once, not the message.
2. The model answers, or asks for a tool. A tool call shows as *Running read file…* in
   the transcript; the result goes back to the model, and the loop continues — for up to
   **25 tool rounds** per message. After that Sirius stops with *Stopping here — this task
   took more tool rounds than expected. Say "continue" to keep going.*
3. Tool output is cut at 24,000 characters so one large file cannot swamp the context.

Small local models that write a tool call as text instead of using the tool API are
caught: Sirius recognises up to six such calls per round and runs them as real tools.

## The tools

**Sirius's own** — the names the tools picker and agent files use:

| Tool | What it does |
| --- | --- |
| `readFile` | Reads a workspace file, optionally a line range (large files: ask for a range) |
| `searchFiles` | Searches workspace files for a literal string, like grep; an optional glob narrows the files |
| `listDirectory` | Lists a directory, folders first; skips `node_modules`, `.git`, `dist` and the like |
| `problems` | The current errors and warnings, optionally filtered by path |
| `editFile` | Replaces one exactly-matching span in a file |
| `createFile` | Creates a file that does not exist yet |

Ask has the first four; Edit and Agent have all six. `editFile` insists the search text
occurs exactly once; if it does not, the model is told
to read the file again or include more context, and nothing is changed.

Every one of these stays inside the workspace: a path that resolves outside the open
folders — `../../etc/passwd`, `/home/you/project/../.ssh/…`, or a symlink in the project
that points elsewhere — is refused with *… is outside the workspace*, for reading,
searching and writing alike. For the web, the agent uses the
[integrated browser](/docs/browser/) tools.

**The editor's own tools, by tier.** The workbench provides terminal, task, test and
browser tools; Sirius offers them in two sets so that a model is never handed more schemas
than it can hold:

- **Core** — every model: run a command in the terminal, read terminal output, keep a todo
  list.
- **Extended** — adds the rest of the terminal and task tools, test running, sub-agents,
  plan review and questions back to you, and the [integrated browser](/docs/browser/)
  tools.

The tier is chosen from what Sirius knows about the model: a model without a tool API gets
core; a local model of 4 GB or more gets extended; a model whose size is unknown gets
extended if its context window is at least 32,000 tokens. Hosted models get extended.

Commands the agent wants to run in the terminal go through the editor's own approval
flow — the prompt you see is the workbench's, with its allow-once and allow-always choices.

**MCP servers and other extensions' tools.** Agent also offers every tool of every MCP
server left ticked in the tools picker, and the tools other extensions contribute, within a
budget sized to the model: small servers are open, a server that does not fit is one
`activate_<server>` tool the model calls to open it, and what it opened stays open for the
conversation. [MCP servers and extension tools](/docs/mcp-servers/) has the budget and the
set-up.

:::note[Changed in 1.118.13: MCP servers' tools]
Earlier releases offered only Sirius's and the editor's tools; a server you added was
never offered, in any mode or agent.
:::

## Edits come back as diffs

`editFile` and `createFile` stream their changes into the editor's chat-editing
session, which is what gives you:

- the change shown as a diff in the file, hunk by hunk;
- **Keep** / **Undo** per hunk and per file, and **Keep All Edits** / **Undo All Edits** in
  the chat;
- **Open Changes in Diff Editor**;
- checkpoints: **Restore Checkpoint**, **Restore to Last Checkpoint** and **Start Over**
  from the conversation, which roll the files back to how they were before a turn.

:::note[Changed in 1.118.8: created files]
A file the agent *creates* is part of the editing session too: **Undo** removes it. In
1.118.7 the empty file was written outside the session first, so Undo left it behind,
empty.
:::

## Ask, Edit, Agent

**Agent** is the editor's own mode; **Ask** and **Edit** are agents Sirius ships, listed
beside it at the top of the picker. Each gets a different set of tools:

| Mode | The model can |
| --- | --- |
| **Ask** | read and search the workspace and see the problems list — it explains and answers, and cannot change a file or run a command |
| **Edit** | all of Ask, plus `editFile` and `createFile` — it changes files and runs nothing |
| **Agent** | all of Edit, plus the editor's terminal, task, test, sub-agent and browser tools, by tier (above) |

Pick per message; it sticks until you change it. The conversation carries over when you
switch. Under an Ask answer, **Make the change** hands the conversation to Agent; under an
Edit answer, **Continue in Agent** does the same. A tool the current mode does not offer is
refused even if a model asks for it by name. Unticking a tool in the chat's tools picker
takes it away in every mode.

:::note[Changed in 1.118.11: Ask and Edit in the picker]
Earlier releases offered only **Agent** in the picker: the editor's own Ask and Edit modes
are hidden in this version of the editor, which expects the chat extension to supply them.
:::

:::note[Changed in 1.118.8: per-mode tools]
In 1.118.7 all three modes offered every tool, so Ask could run terminal commands and
edit files.
:::

## Your own agents

An agent is a Markdown file ending in `.agent.md` in your project's `.github/agents/` folder:
a name, a description, the tools it may use, and its instructions.

```markdown
---
name: Reviewer
description: Reviews code without changing it
tools: ['readFile', 'searchFiles', 'problems']
---
Review the code you are pointed at. Lead with the riskiest problem.
```

It appears in the mode picker beside Agent, Ask and Edit. Sirius gives it exactly the tools
it lists — never more than Agent would have — and follows its instructions. Sirius's tools
are the six above; the editor's are listed in the chat's tools picker; an MCP server's go in
as `github/*` for the whole server or `github/create_issue` for one tool
([MCP servers](/docs/mcp-servers/)). A `.github/agents`
folder you create while Sirius is running is picked up at the next start. **Configure Custom
Agents…** at the bottom of the picker lists them, opens one to edit, and shows or hides each
in the picker.

:::note[Changed in 1.118.11: your agents' tools and instructions]
Earlier releases gave every custom agent all of Agent's tools, terminal included, and
dropped its instructions.
:::

## Thinking

Models that reason (Claude, Gemini, and local models whose server declares `thinking` —
🧠 in the picker) are asked to, at the effort you set (**Sirius: Set Thinking Effort
Level**); **Sirius: Toggle Thinking** turns it off. The reasoning shows in the transcript as
a collapsible *Thinking* section above the answer.

:::note[Changed in 1.118.8: thinking shown]
In 1.118.7 the reasoning was requested but not shown.
:::
