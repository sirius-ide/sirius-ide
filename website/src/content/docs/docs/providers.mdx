Sirius talks to a provider's API directly from your machine — there is no Sirius account
and no relay. Eight hosted providers take a key; four local or self-hosted ones take none.
You add them in the editor's **Language Models** editor — **Manage Models** — where each one
is a provider of its own.

| Provider | Key | Endpoint | Models |
| --- | --- | --- | --- |
| Anthropic | yes | fixed | Claude Opus 5, Fable 5, Sonnet 5, Opus 4.8, Haiku 4.5 |
| Google Gemini | yes | fixed | Gemini 3.5 Flash, 3.1 Pro, 3.1 Flash Lite; replaced by the live list your key can see |
| OpenAI | yes | `https://api.openai.com/v1`, or a Base URL you give it | discovered |
| OpenRouter | yes | fixed | discovered |
| Groq | yes | fixed | discovered |
| DeepSeek | yes | fixed | discovered |
| Mistral | yes | fixed | discovered |
| xAI | yes | fixed | discovered |
| Ollama | no | found at `http://localhost:11434` with nothing added; add another host | discovered |
| LM Studio | optional | found at `http://localhost:1234/v1` with nothing added; add another server | discovered |
| llama.cpp / vLLM | optional | found at `http://localhost:8080/v1` with nothing added; add another server | discovered |
| OpenAI-compatible (custom) | optional | the Base URL you give it, with the `/v1` suffix | discovered |

*Discovered* means Sirius asks the server for its model list (`/models`, or Ollama's
`/api/tags`), so what you see is what the endpoint offers. Every provider except Anthropic,
Gemini and Ollama is driven through the same OpenAI-compatible chat-completions adapter.

## Adding a provider

Open **Manage Models** — at the bottom of the chat's model picker (open *Other Models* if it
is folded), **Chat: Manage Language Models** in the Command Palette, or **Sirius: Manage
Models** — and choose **Add Models…**.
Pick the provider, give it a name (two of the same provider need different names), and paste
the key into the password box; LM Studio, llama.cpp and the custom endpoint also ask for the
server's URL, and their key may be left empty. **Sirius: Set API Key** does the same from the
Command Palette.

Sirius then checks the provider with one cheap request — listing its models, which costs
nothing — and its models appear in the chat's model picker. If the check fails, the provider
shows as a red row in Manage Models saying which it was: *rejected the API key (HTTP 401)*, or
*did not answer at …* for a server that is not running or a wrong URL.

In Manage Models you can also:

- **Configure** a provider — a new key, another URL — or **Delete** it, key and all;
- add the **same provider twice** — two OpenAI-compatible servers, a second Ollama machine,
  a work and a personal key — each under its own name;
- **Hide** a model you never use, so the picker stays short;
- search and filter by provider, capability or visibility.

Where to get a key: [Anthropic](https://console.anthropic.com), [Google](https://ai.google.dev),
[OpenAI](https://platform.openai.com/api-keys), [OpenRouter](https://openrouter.ai/keys),
[Groq](https://console.groq.com/keys), [DeepSeek](https://platform.deepseek.com/api_keys),
[Mistral](https://console.mistral.ai/api-keys), [xAI](https://console.x.ai).

:::note[Changed in 1.118.12: Manage Models]
Earlier releases took keys only through **Sirius: Set API Key**, did not check them, and
listed every provider under one entry; endpoints were settings. On its first start 1.118.12
moves the keys you had — and a custom or OpenAI endpoint from settings — into Manage Models,
one provider each, and tells you so. They stay in the system keyring throughout.
:::

## Where keys live

The editor keeps a provider's key in its secret storage, which encrypts it with the operating
system's facility and keeps the result in the editor's own database — never in a settings
file, never in `chatLanguageModels.json` (which holds only a reference to it), never in
Settings Sync:

- **macOS** — the Keychain.
- **Windows** — DPAPI, the user-account encryption built into Windows.
- **Linux** — libsecret (GNOME Keyring) or KWallet, whichever the desktop provides. On a
  system with neither, the editor warns that no OS keyring could be identified and keeps
  secrets in memory only, so keys do not survive a restart; its dialog offers a weaker,
  file-based store (`--password-store=basic`, written to `~/.sirius/argv.json`). Install
  `gnome-keyring` or run KWallet to keep keys properly. The Arch package lists `libsecret`
  and `gnome-keyring` as optional dependencies for exactly this reason.

### Keys that used to be settings

Early versions kept keys in `sirius.ai.anthropic.apiKey`, `sirius.ai.gemini.apiKey` and
`sirius.ai.openai.apiKey`. Those settings are deprecated. On every start, Sirius moves any
value it still finds there into the keyring, clears the setting, and from there into
Manage Models as above. Nothing to do by hand.

## Local servers and your own endpoint

- **Ollama, LM Studio, llama.cpp** on their usual ports need nothing added. Where Sirius looks
  for them is a setting — `sirius.ai.ollama.endpoint`, `sirius.ai.lmstudio.baseUrl`,
  `sirius.ai.llamacpp.baseUrl` — read from your user settings only, never from a project's
  `.vscode/settings.json`; Tab completion uses the same Ollama and llama.cpp endpoints.
  Another machine or port is another provider in Manage Models. vLLM uses the llama.cpp
  entry.
- **OpenAI** through an Azure deployment or a corporate proxy: give the OpenAI provider that
  Base URL.
- **Anything else OpenAI-compatible**: add *OpenAI-compatible (custom)* with its `/v1` URL —
  as many as you have, each with its own name and key.

Anthropic and Gemini endpoints are fixed. OpenRouter requests carry the `HTTP-Referer` and
`X-Title` headers OpenRouter asks apps to send, identifying Sirius IDE as the client.

## What a request contains

The messages of the conversation, the context the editor attached (the active file and
selection, anything you added with the context controls, the [rules files](/docs/rules-and-context/)),
the results of tools the agent ran, and the request settings — `sirius.ai.maxTokens`,
`sirius.ai.temperature`, streaming on by default. It goes to the provider you picked and
nowhere else. The [privacy statement](/privacy/) is the binding version of that sentence.
